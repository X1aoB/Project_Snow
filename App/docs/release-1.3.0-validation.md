本次将两个类别分开处理：人物形象关注角色表达、互动方式和主动提议；角色事实关注已发生的原作事件、正式关系和检索证据边界。后台主动消息的开关不作为人物形象的修复手段。

## 人物形象

检查 `pipelines/build_dialogue_profiles.py` 和 `backend/snow_app/mvp_service.py` 发现：

- 角色装甲形式的说话人标注未被人物别名覆盖，导致自身台词漏选。米娅的资料页 `629d1d35df4e` 是可核对的来源例子。
- 人格提示只保留部分 statement，未保留实际 identity evidence；截断和去重也可能让同一类叙事挤占互动表达。
- 通用聊天规则过度限制了自然提议。

通过 `backend/snow_app/dialogue_persona.py`，按精确角色归属及装甲元数据恢复说话人别名。运行时从既有只读文档构建独立的表达参考，不需要重建生产数据包；构建器也复用别名逻辑，供后续版本化派生包使用。最多保留两条身份引文与八条短台词，分散来源页，并缓存不含用户内容的结果。参考只用于表达方式，不能成为当前场景或正式关系事实。

通用规则允许符合人物形象、可拒绝的小提议；校验继续阻止擅自安排会面、移动和共同执行计划。不是强制每轮提问，也不把所有角色变成相同的外向性格。

`tests/test_dialogue_persona.py` 的九项合成测试覆盖装甲说话人、另一角色的通用别名、旁白/时装隔离、来源预算、构建器、缓存失效与隔离、提示接入和提议边界。只读资料审计中，米娅可识别的自身台词从 64 条变为 332 条；22/22 角色均有明确自身台词参考。自动化测试验证资料选择、提示和保护边界，不代表真人已评价模型的人物表现。

## 角色事实与检索

正式关系来自版本化的 `config/public_knowledge/character_relationships.v1.json`，当前名单有八人，不包含米娅。事实修复不能靠增加亲密语气来替代。

检查 `backend/snow_app/mvp_service.py` 发现：关系证据按词命中可能误收否定、愿望或第三人称；关系事实边界没有常驻所有普通聊天；关系名单校验覆盖不完整；检索在重排前过早截断。会话前提中的肯定、否定和假设也需分别验证。

修复引入 `backend/snow_app/factual_grounding.py`，分离肯定断言、否定/纠错、假设、愿望和他人叙述；版本化正式关系边界常驻每轮系统提示。名单校验覆盖全部注册角色，生成检查与既有最多两次调用的修复链路共用同一边界；无法纠正的正式关系断言被拒绝，流式检查在发布错误文本前拦截。

检索保留过滤后的候选池直到角色和意图重排结束，再执行返回数量限制；重排入口再次检查角色/时装准入。回归直接调用真实 retrieve 及生成/修复链路，不只验证辅助函数。

`tests/test_factual_grounding.py` 最初在旧实现上得到 83 个失败、5 个通过和 8 个通过子场景，确认新增回归能够发现旧缺陷。最终两类新增测试合计 28 项、188 个子场景通过。所有回归使用合成/临时数据；原始 Data、审核决定、用户聊天和线上运行数据不作测试输入或写入目标。
