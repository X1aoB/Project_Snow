# 1.3.0 人物形象与角色事实修复

## 范围与证据

本次将两个类别分开处理：人物形象关注角色表达、互动方式和主动提议；角色事实关注已发生的原作事件、正式关系和检索证据边界。后台主动消息的开关不作为人物形象的修复手段。

2026-11-14 的反馈未附对话或诊断信息。因此下文是对现有实现的可复现缺陷分析，不声称已经重现反馈者当时的完整对话。

起点为 1.2.1，提交 `2cbf9f1fc225614d0a953c37d49a6cd39151522b`。生产版本与 build-info 已只读核对一致。基线 `502ec99412bef843c37e4b31a53df8fa9faeb33c` 保留。修复在 `codex/snow-1.3.0-cognition` 独立工作树进行。

## 人物形象

检查 `pipelines/build_dialogue_profiles.py` 和 `backend/snow_app/mvp_service.py` 发现：

- 角色装甲形式的说话人标注未被人物别名覆盖，导致自身台词漏选。米娅的资料页 `629d1d35df4e` 是可核对的来源例子。
- 人格提示只保留部分 statement，未保留实际 identity evidence；截断和去重也可能让同一类叙事挤占互动表达。
- 通用聊天规则过度限制了自然提议。

通过 `backend/snow_app/dialogue_persona.py`，按精确角色归属及装甲元数据恢复说话人别名。运行时从既有只读文档构建独立的表达参考，不需要重建生产数据包；构建器也复用别名逻辑，供后续版本化派生包使用。最多保留两条身份引文与八条短台词，分散来源页，并缓存不含用户内容的结果。参考只用于表达方式，不能成为当前场景或正式关系事实。

通用规则允许符合人物形象、可拒绝的小提议；校验继续阻止擅自安排会面、移动和共同执行计划。不是强制每轮提问，也不把所有角色变成相同的外向性格。

`tests/test_dialogue_persona.py` 的十项合成测试覆盖装甲说话人、另一角色的通用别名、旁白/时装隔离、来源预算、构建器的跨角色语音隔离、缓存失效与隔离、提示接入和提议边界。只读资料审计中，米娅可识别的自身台词从 64 条变为 332 条；22/22 角色均有明确自身台词参考。自动化测试验证资料选择、提示和保护边界，不代表真人已评价模型的人物表现。

## 角色事实与检索

正式关系来自版本化的 `config/public_knowledge/character_relationships.v1.json`，当前名单有八人，不包含米娅。事实修复不能靠增加亲密语气来替代。

检查 `backend/snow_app/mvp_service.py` 发现：关系证据按词命中可能误收否定、愿望或第三人称；关系事实边界没有常驻所有普通聊天；关系名单校验覆盖不完整；检索在重排前过早截断。会话前提中的肯定、否定和假设也需分别验证。

修复引入 `backend/snow_app/factual_grounding.py`，分离肯定断言、否定/纠错、假设、愿望和他人叙述；版本化正式关系边界常驻每轮系统提示。名单校验覆盖全部注册角色，生成检查与既有最多两次调用的修复链路共用同一边界；无法纠正的正式关系断言被拒绝，流式检查在发布错误文本前拦截。

检索保留过滤后的候选池直到角色和意图重排结束，再执行返回数量限制；重排入口再次检查角色/时装准入。回归直接调用真实 retrieve 及生成/修复链路，不只验证辅助函数。

`tests/test_factual_grounding.py` 最初在旧实现上得到 83 个失败、5 个通过和 8 个通过子场景，确认新增回归能够发现旧缺陷。最终两类新增测试合计 30 项、229 个子场景通过，涵盖未来条件、反向婚姻谓词和纠错中的主张归属。所有回归使用合成/临时数据；原始 Data、审核决定、用户聊天和线上运行数据不作测试输入或写入目标。

## 发布验证

版本字段统一为 1.3.0。公共 v1、public-state-2、IndexedDB v4 和请求快照保持兼容；本次不新增数据库迁移。

最终定向回归：`test_factual_grounding.py`、`test_dialogue_persona.py`、`test_application_layer.py`、`test_generation_latency_v2.py`、`test_review_state_preservation.py`、`test_mvp_22_product.py`（排除私有运行数据测试）合计 **230 passed、725 subtests passed**。两个新增文件已加入 CI 的公共 API 回归列表。真实资料的独立只读投影检查确认 22 位角色的选中台词都归属于自己，米娅的正式关系规则为尚未确立恒约。

本地完整可移植套件得到 **1913 passed、489 skipped、2249 subtests passed、1 failed**。唯一失败为 Windows 默认 GBK 解码已有 UTF-8 `ops/deploy.sh`；以 `python -X utf8` 重跑 `test_stage_never_reconciles_shared_services` 后 **1 passed**。未放宽断言、未更改部署脚本。上述最终定向回归包含完整套件之后的审阅修正；完整日志及 JUnit 保存在忽略的 `runtime/release-validation/1.3.0/`。精确发布提交还须通过 Linux CI 全量检查。

功能修复已通过 PR #122 的 CI 并合并；合并提交 `e61c88d1916be71a4b8c9c37c75f74c0acb3bbe9` 的 Linux CI 和签名发布证明也通过。发布审查发现，仅增加 CI 测试清单就会通过风险分类触发共享 embedding 重建，且按最近已构建祖先选择基线可能选中尚未上线的候选。因此该候选没有暂存；其原始签名产物保持不变。

发布流程补充修复将验证范围与强制重建分开：实际构建输入指纹不变时，复用显式批准的生产 embedding digest；输入变化、缺少指纹或明确的安全刷新仍重建。PR 和发布比较均绑定同一批准基线，缺少、格式错误或不可拉取时失败，不退回任意祖先镜像。批准基线经线上运行镜像、已晋级标记和原签名清单三方只读核对后配置；这不构成共享服务变更授权。复用镜像仍进行新的漏洞扫描，重建仍要求向量等价验证。

状态：已完成实现与定向验证，尚未发布。补充修复后的精确提交仍须通过 CI、公告预检、候选身份、浏览器检查和回退锚点，再进入既有候选验收及晋级流程。未进行真实付费模型人格评测，不能将自动测试写成人工质量批准。
