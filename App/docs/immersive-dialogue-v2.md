# 对话分域与自然赴约 v2

本次以 PR #75 的聊天修复为基础，保留当前地点目录、最新已入库原作状态、
public v1、public-state-2 和 IndexedDB v4。新能力默认关闭，候选验收后再手动推广。

## 行为

`TurnFrame` 将日常、原作回忆和本会话回忆与时间、引用、否定及行为分别判断。
混合句按分句处理。日常没有稳定资料命中时不填入无关旧剧情；原作过去的
地点与活动不被当前场景接管。会话摘要用于连续性，不直接成为已确认事实。
同轮生成提供结构化邀请决定，不需要角色使用固定接受措辞，也没有新增模型分类调用。

邀请按钮和自然输入共用目录与解析器，支持明确地点、房间和当前约定的短句续接。
服务端验证目标、时间和回应一致性后，面对面共同移动，通讯器建立等待会合记录。
纯赴约使用无模型场景动作，确认位置后进入面对面；混合内容仍按一次主生成处理。
打开通讯器保持位置，取消约定结束等待活动，联系人选择不执行物理移动。
未来和待定约定的卡片在两种媒介均可查看、折叠和取消；只有当前已确认等待会合
才提供赴约入口。取消未来约定不移动角色、不改日程活动，也不将每日种子升格为确认场景。

v2 会话中，长聊与重开保持签名场景。跨日继续昨日场景只恢复当前角色已确认
位置及有效约定，其他角色的日程仍刷新；从今天开始结束旧场景和未履行约定。
v1 的原跨日行为不变。迟到结果不能覆盖新分段、日期或场景版本。

日常经历独立于原作证据：用户自述、角色承诺和已验证场景事件保留不同来源等级。
普通共同互动需要当前面对面同地、输入动作及已验证角色动作的双来源支持；
模型提供的候选或摘要不能自行建立过去经历、正式关系和重大剧情事实。
完整索引只存浏览器，本轮最多发送十二条相关记录；签名上下文、分段标识及所选
记忆凭证的 UTF-8 JSON 合计不超过 8KiB。新请求按相关性和字节预算选择，原请求的
恢复封套保持不变，不因开关或预算调整而裁剪后重发。
保留期、角色删除和清空同时处理索引；旧签名、导入历史不恢复权威场景。
长聊后询问共同地点时，优先选择已确认、有地点来源的经历；未履约承诺和用户自述
保持各自来源等级。零历史的首次场景请求依原线程元数据保留原 UUID，删除旧线程
留下的无来源上下文则退役。

## 接口与恢复

- `/public/v2/chat/stream` 接受 `public-dialogue-v2` 封套，包括原 ChatRequest、
  segment ID、签名 session_context_package 和可验证的 memory_candidates。
- `/public/v2/scene/action` 接受 `public-scene-action-v2`，支持 resolve、
  open_communicator、join_character、join_rendezvous 和 cancel_rendezvous。
  约定动作核对 rendezvous ID，不调用模型或到场生成。
- config 增加能力协商；旧请求字段集合与哈希不变。新快照包含固定协议、
  路径和封套，已发出的请求不自动切换版本。
- 场景、签名上下文和完整回复写入同一请求结果事务，成功 ACK 后交付。
  浏览器按归属检查后在同一 IndexedDB 事务保存世界、上下文、索引和消息。
- v2 恢复使用 `X-Snow-Recovery-Only: 1`：查询原主体、UUID 与完整快照，不重新领取。
  当前完整结果缓存为十分钟；缺失或过期返回 410，快照冲突返回 409。
  不因网络断开、回退或过期而自动改 UUID、重生成或降级 v1。

场景事件和恢复状态不计入有效角色回复；模型首段五秒目标没有因此被宣布达成。

## 开关与验收

独立开关均默认 false：`PUBLIC_DIALOGUE_DOMAINS_V2`、`PUBLIC_SCENE_ACTIONS_V2`、
`PUBLIC_SESSION_MEMORY_V2`。新协议元数据与分域检索分离，所以只开启场景或记忆
仍能生成对应结构。关闭开关不阻止已确认 v2 结果的只读恢复，不删除本地索引。
候选开关从独立的 `/etc/project-snow/candidate-flags/<40位提交SHA>.env` 读取，
只接受这三个布尔开关。该文件须为 root:root、0600、无符号链接和额外硬链接，
父目录也不能由其他用户写入；生成版本环境后不再依赖覆盖文件。不修改共享 public.env；
接受回执必须记录实际开关、源码/镜像、旧界面回退、公告及候选可见行为。

普通 CI 只用合成数据和模型替身，覆盖十五地点、二十二角色、否定/引用/时间、
同轮结构化接受、来源隔离、跨日、断线、失败 ACK、重复操作、保留期、移动端及减少动态效果。
PostgreSQL 检查包括实际 baseline old/new/old JSON 缓存兼容和事务失败不提交。
真实延迟只通过已授权的正常聊天匿名计时收集，不新增付费测试调用。
