# 5 秒首段回复与动效候选验收

日期：2026-10-13。代码基线：`6711f6a`，工作分支：`codex/response-motion`。

本文件保留原始候选与整合时的验收记录。后续已批准上线的版本状态与新增计时验收见 [后续验收记录](response-motion-followup.md)。

本候选实现生成链路、受控分段交付及前端动效优化。未调用真实付费模型、未部署生产、未取得真人自然度或动效批准。**各型号首段 P95 ≤5 秒仍待真实使用样本验收，不能用输入提示或合成测试代替。**

## 行为和开关

| 配置 | 默认 | 行为 |
| --- | --- | --- |
| `PUBLIC_CHAT_LATENCY_V2` | `true` | 精确型号参数、公开聊天紧凑输出、短自然等待 |
| `PUBLIC_VERIFIED_BLOCK_STREAM` | `false` | 显式开启后，已核实型号采用真实上游 SSE；符合条件的正文块可在整条完成前交付 |
| `PUBLIC_MOTION_V2` | `true` | 360ms 模式过渡、轻量面板/消息动效、快进与减少动态 |

`/public/v1/config` 新增 `features` 和公开的 `model_profiles`。`verified_block_replay` 是协议能力，关闭新分段发布开关不会关闭已确认内容的恢复。旧客户端不协商协议 2，继续使用原 `meta/delta/state/done/error`。

精确型号配置仅针对固定官方端点，不把自定义或未核实型号推断成已关闭思考。未知型号保持可选、使用原有整答处理，不静默换模型。输出上限仍为 1600；删除重复的 `answer` 生成及助手报告字段，由服务端从 `content_blocks` 派生兼容正文。

静态角色投影采用 64 项有界缓存，键包含数据版本、资料文件时间、内容指纹、提示版本和角色，返回独立副本。证据仅对完全相同的来源和内容去重；同文不同来源、同一文档不同片段仍保留，不修改历史、原始检索结果或守卫上下文。

首批提前交付仅覆盖可独立检查的普通闲聊 message/speech。完整记忆仍参与生成；涉及移动、预约、剧情事实、特殊互动或无法独立检查的回合等待整条。立绘候选本身不会关闭闲聊分段，但实际演出元数据、动作或状态提案不在提前交付范围。

## 协议、计费与恢复

新客户端发送 `X-Snow-Stream-Version: 2`，服务器增加：

- `progress`：真实执行阶段，不含虚构百分比和思考正文。
- `committed_block`：`request_id`、`character_id`、从 0 连续的 `sequence`、稳定 `block_id` 及 `block`。
- `done.timings_ms`：明确白名单内的非负计时值，不含任意供应商诊断。

正文经过累计前文守卫、公开内容检查及脱敏投影检查，且数据库确认提交后才可见。最终正文必须原样保留已确认前缀。后续失败发送 `error.partial=true`，浏览器保留确认内容并标记未完成；不自动重新生成。

同 UUID 重连重放已有片段和最终结果，另一进程拥有请求时只读取数据库。数据库最终写入失败或确认丢失时保留原请求快照，以同一 UUID 核对结果。断开浏览器不会取消已接受的付费任务；租约和现有生成容量继续约束工作。

迁移 `20261013_0008` 接在主线 `20260926_0007` 后，仅添加 `public_request_blocks`，保留 public v1、public-state-2、IndexedDB v4 与请求快照。发布前必须完成迁移及运行角色权限核验。应用回退保留新表；回退旧二进制仍须排空任务、等待租约并执行既有失联请求恢复流程。已经落盘的片段随原请求缓存期限清理，不是永久聊天归档。

## 前端验收

- 发送立即显示本地消息；约 250–400ms 出现输入反馈，首答最早约 600ms，真实等待抵扣该窗口。
- 气泡入场约 180ms，后续段间 200–450ms，累计额外间隔最多 1.2 秒；历史和重放不重播。
- 面对面保留逐字呈现与已收到内容快进；装饰动画不占用业务请求锁。
- 切换位置请求立即开始，确认后执行约 360ms 的可取消画面过渡；到场模型等待在对白区域表达，不阻塞整屏。
- 草稿、滚动和焦点保持；退出画面不可交互。隐藏页面及系统减少动态会收束动画，移动端采用较轻效果。

人工验收覆盖桌面及 390/320px、软键盘、长历史、连续切换、到场失败、表情解码失败、部分回复、后台恢复及键盘操作。自动化测试不等于真人批准。

## 性能样本与验证方法

浏览器只在内存保存最近 100 条匿名计时，不额外发送遥测请求。以 `window.__projectSnowPerformance.getSamples()` 导出作为验收输入。`project-snow:reply-timing` 通知请求终态；若此时正文尚未绘制，其首绘字段为 null，后续 `project-snow:reply-visible` 通知首次可见。导出包含完成/失败/部分回复，不包含正文、凭证、原始请求编号或未知私人模型名。不同导出批次避免重复采样。

在 `App` 下运行：

```text
python scripts/latency_report.py timing-export.json
```

输出按全部请求、具体型号、媒介、历史长度、排队、改写和恢复分组，报告样本数、P50/P95、缺失正文、超过 5 秒及失败/部分回复。每个待验收型号至少 30 个新生成样本；原生成失败和缺失测量保留在成功率分母。手动使用原 UUID 恢复的样本另列，缓存回放不能提高模型生成达标率。自动断线重连仍沿用本轮原始发送时间。首段没有实际进入当前可见区域时记录未测量，不能当作立即可见。

服务器首个上游 content 事件可能仍是结构化元数据；`provider_first_content_ms` 不等于有效正文。`first_committed_block_ms` 是本轮请求到首个确认正文块，浏览器首绘才是最终体验指标。`durable_commit_ms` 在事务 ACK 后才得到，仅当前响应和服务日志具备；缓存回放缺少它时保留未测量，不能补零或作为本轮新生成耗时。

面对面逐字显示分别记录首字绘制和完整首段可见：`ready_to_paint_ms` 观察首字绘制，`send_to_first_effective_ms` 等第一段 speech 正文完整显示才记值；打字尚未到完整句段时后者为 null。通讯器完整气泡同帧满足两者。保留的自然等待单列，不混入就绪后的渲染开销。

首段目标为 ≤5000ms；独立记录正文就绪至绘制时间及自然等待；普通聊天目标 P95 ≤5000ms、成功且首段按时比例 ≥95%。长剧情和异常分层展示，仍保留在总体分母。上游达不到的型号如实标为未达标。

自动验证使用合成模型/临时数据，包括：完整 MVP 调用在上游结束前提交首段、隐藏推理隔离、畸形流与 Unicode、前缀后续违规、UUID 去重与 ACK 丢失、数据库失败、前端分段与减动测试。真实 PostgreSQL 使用任务独立的 17.11 实例，覆盖 `502ec99` 和 `6711f6a` 的 old/new/old；测试实例已停止。
