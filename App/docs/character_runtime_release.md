# 全角色分层表现发布

角色媒体包可以向当前小吉终端界面提供每名角色的 18 个基础表情和独立的剧情动作目录。服务端只下发当前角色、当前已发布清单内的动作；删除动作后不足 3 项的角色仍然有效。文字聊天保持普通聊天显示，面对面场景才启用表情与动作。

浏览器在全部原生图层完成解码后一次切换画面。切回当前表情、切换角色或返回文字界面都会使旧解码请求失效。新角色清单优先于静态后备图；原有版本化舞台发布的哈希校验与米娅静态后备仍然保留。

## 精确素材与批准记录

正式清单可放入独立的批准目录，避免修改历史制作文件：

```powershell
python scripts/build_character_media_release.py `
  --expression-root <private-expression-root> `
  --approval-root <private-expression-root>/releases/U4/approvals `
  --rights-path <separate-public-rights-decision.json> `
  --avatar-source-root <verified-avatar-source-root> `
  --analyst-source-root <verified-analyst-source-root> `
  --version <new-immutable-media-version>
```

目录必须完整包含 22 个角色的批准清单。校验会绑定完整底图、层栈、原始参考、剧情设计、用户事件与文件 SHA256。明确的动作清单可以覆盖历史数量下限，但必须和独立批准事件中的保留 cue 完全一致，不能恢复用户已经移出的动作。

标准底层只能清除原底图像素或降低其透明度；仍可见的 RGB 必须不变。已审阅的完整动作底层需要额外逐项绑定用户事件与封存 U4 的原图、图层、位置、尺寸和运行版本选择。空底层仅限完全替换动作所需的原尺寸首层；空底图、空预览或空头部仍被拒绝。

原生图层直接保留已批准 PNG 的字节与 SHA256，不缩放或重新编码。Chromium 对 PNG 与 WebP 的半透明解码可能产生不同的预乘颜色，因此“无损 WebP”不能保证分层合成与已审 PNG 相同。384 px 头像和 1024 px 高兼容立绘使用无损 WebP，原生舞台使用原始 PNG。发布校验在隔离 Chromium 中逐像素比较真实层栈与批准预览；旧 PIL 合成清单继续使用原有严格校验。

## 验证与发布边界

行为回归覆盖角色目录、已删除 cue 的重放、慢解码竞态、文本/面对面切换、当前主线舞台发布后备及模型配置。素材契约回归覆盖批准哈希、非法图层/尺寸、透明度、错用预览、被删除动作恢复和未批准动作底层。

U4 艺术验收覆盖 503 个候选；当前选择为 396 个基础状态和 60 个特殊动作，共 456 个运行表现。历史 57 项版本偏好保留；肴的三种特殊表现从本次全部批准的候选中选择 B、A、B，选择来源单独记为制作方选择。

图片验收、素材公开权利处理和服务器候选晋级分别记录。此代码不更改 `config/public_release_artifacts.json`，不把本地审阅包标为已公开，也不授权覆盖其他任务的候选槽。最终媒体版本与摘要需要经过独立权利确认、候选部署验收和具体验收回执后进入正式发布。
