# 2026-10-14 聊天反馈修复验收

本轮依据香港时间 17:35–17:49 提交的四条反馈修复当前版本的问题。
反馈和结构化诊断通过只读查询取得；修复记录没有复制附带聊天正文、
联系方式、凭证或私人 Provider ID。服务器原反馈及处理状态保持不变。

## 问题、证据与修复

- 文字见面邀请：当天出现一组在模型调用前快速失败的请求。合成用例
  复现了文字中的见面邀请被 MVP 提前切成面对面，继而触发异地冲突的路径。
  公开聊天现在保持请求中明确的媒介；见面预约和实际位置切换沿用原流程。
  本地 MVP 的默认转换行为、真正面对面的异地校验仍保留。
- 气泡与等待：完成事件曾取消逐段显示，再一次性展示全部已确认气泡。
  现在保留已显示前缀并接续后续节奏；模型完成和输入解锁独立于呈现。
  日常输入提示窗口调整为 500–750ms，首段自然窗口仍按发送时间抵扣。
- 模式归属：错误提示及恢复入口按角色、媒介和会话片段归属显示。
  通讯器失败不会污染面对面，仍可返回原模式恢复对应请求。
- 阅读位置：上翻历史时保留可见消息及其视口偏移，在底部时跟随新消息。
  自动锚定采用即时滚动，布局、图片及窗口尺寸变化也按同一规则处理。
- 面对面呈现：安装完整呈现队列后再绘制，不在中间空帧重播初始描述；
  当前对白没有动作时不回落到最初活动。旧协议的类型化动作保留独立类型。
- 可靠性：已确认完成的回复不会因本地保存或装饰动画异常变成可重新收费的失败。
  收到终态后不等待连接 EOF；手动恢复使用原 UUID 并保留已经显示的内容。
  断线恢复时立即提供停止等待入口，不让自然输入提示的延迟挡住取消操作。
- 反馈关联：失败轮和明确选中的消息各自绑定对应请求；到场反馈通过原 UUID
  查询同用户的到场缓存命名空间，并核对角色及媒介，不拼接另一轮诊断。
  关闭附带上下文时继续只发送用户填写的正文与可选联系方式。

现有反馈包含“旧回复成功诊断 + 新失败错误”的错关联，因此不能仅据该诊断
断言实际失败请求生成成功。线上日志将异常信息脱敏为是否存在；合成复现链
与零调用症状一致，但不宣称已经取得某次生产请求的完整异常调用栈。
